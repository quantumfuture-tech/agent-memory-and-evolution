# session-handoff · 跨会话记忆（能力1 保存 / 能力2 读取）

> 术语：**记忆包**（旧称 store，因多次被误读为“店”而改名）；**接管**（旧称“上 store”）、**交回**（旧称“下 store”）。目录名仍为 `.handoff/<包名>/`。

本 skill 是一份**元约定**：不携带任何具体任务内容，只提供（a）两个能力（保存/读取）、（b）固定锚点、（c）读取元约定（能力2 的硬编码接手算法）、（d）保存元约定、（e）对任务约定（PROTOCOL.md）的硬性格式要求。具体任务的记忆内容全部由 `.handoff` 目录承载。

## 0. 固定锚点与关键概念

- **项目根**：最近的含 `.git` 的祖先目录；不存在则用当前工作目录（cwd）。
- **记忆目录**：`<项目根>/.handoff/` —— **一个项目只有一个**。
- **记忆包**：记忆目录下的一个**子目录**（`<项目根>/.handoff/<记忆包>/`），里面装这个记忆包**自己的一整套**（`PROTOCOL.md` ＋ **本资产表**里声明的文件）。**记忆包名可缺省**——缺省时「记忆包」就是 `.handoff/` 本身（单记忆包项目的形态）。
  - **一个会话可以持有多个记忆包**：能力 1／2 都是「对某个记忆包执行」——读了几个记忆包、动了几个记忆包，就有几对 READ／SAVE。
  - **接管记忆包** = 在**别人的记忆包**（另一个子目录）里执行能力 2，以此取得**写权**（= 可写这个记忆包的文件；对价见 §1、§2 步骤 2）。**一个记忆包同一时刻只该有一个持有者**：若你发现它正在别处被推进（封条／总账本），先别写，问用户。
  - **交回记忆包** = **先完整负责**（对该记忆包跑一次完整能力1，含 SAVE）→ 再**交回**推进权与文件修改权。它只表示"**我这一路不再持有它**"，**不改变该记忆包本身**（别人仍可接管它）。交回之后**不许再写它的文件**——要写就重新上。
  - **持有 = 订阅**：睡醒时只跟进**你持有**的记忆包（见 §1 步骤 0／2）；**已下的不订阅**（不查封条、不重载，只从世界级账本顺带知道）。
  - **睡醒** = 能力2 的**固定第 0 步**：**先看世界**（世界级两份＝现在有什么 ／ 我不在时谁做了什么）→ **再看手上的记忆包**（封条＝它有没有在我睡时被推进过）。两个目的：**消除惊奇**、**接续最新**。
  - **封条** = **状态画像文件（`role: state-summary`）末行的戳**，其中 `updated` 精确到秒——它是"这个记忆包最后一次自我更新的时刻"，**只需读一行**即可判断新旧（见 §1 步骤 2、§3.5）。
- **自我**：这个记忆包「如何活过来」的全部依据——`PROTOCOL.md` ＋ **本资产表**里声明的文件（**记忆包**是它住的那个子目录；一个自我 = 一份 `PROTOCOL`）。
- **世界级两份文件**（住在 `.handoff/` 顶层，**不属于任何记忆包**，**可选**）：
  - **总注册表（`REGISTRY.md`）**：这个世界**现在有什么、归哪个记忆包**，用**用户能懂的话**写（这是什么 / 怎么用）。**总注册表**是**路由**——碰到一台坏掉的机器，从它查出该上谁的记忆包去修。
  - **总账本（`CHANNEL.md`）**：公用流水账——「谁做了什么」（C 修了机器 / B 建了农场 / A 编了一本书）。**只能追加，不能改写**。署名写**记忆包的负责者**：接管记忆包代做的，也写原本那个记忆包。
- **读取约定（任务约定）**：固定位于 `<记忆包>/PROTOCOL.md`（记忆包名缺省时即 `<项目根>/.handoff/PROTOCOL.md`）——它是"读取约定"，不是存储草稿。
- **概念**：接手必读清单（handoffReadList）、资产组织方式（**资产表**）、引导注入（必读文件在接手时全文读入，可携带自由格式规约）；**指针** = 指向别处的引用（只放「在哪」，不放内容）。
- **约定 vs 规约**：**约定**指文件（**读取约定** = `PROTOCOL.md`；**自定义约定** = `role: guidance` 文件）；**规约**专指被注入的**行为内容**（注入规约）。
- 元约定格式版本号（conformsTo）：`handoff-meta-v1`。任务约定必须在元信息里声明 conformsTo 以确认按本格式撰写。

## 1. 能力2：读取（读取元约定，硬编码接手算法）

用户在**新会话开头**说"使用2 / 恢复 / 接手 / LOAD / 带我找回状态"时执行。此算法是硬编码的固定顺序，不得跳过、不得改为自由反推：

> **接管记忆包**：若要动的是**别人的记忆包**（另一个子目录），就在那个记忆包上执行本算法——**整份读，不得定点、不得跳步**。这是取得**写权**的对价（见 §2 步骤 2）。
>
> **只读不写**：只想看一眼别人记忆包里的某个文件 → **定点读即可**，那不算接管记忆包。**整份读是写权的对价，不是读的门票**（否则该写的会因为"太贵"而绕开）。

0. **睡醒（固定第 0 步，不得跳过）**：先看**世界**，再看**手上的记忆包**。
   - **(a) 读世界级两份**：`REGISTRY.md`（现在有什么、归哪个记忆包）→ 路由；`CHANNEL.md`（我不在时谁做了什么）→ **消除惊奇**。
     **若不存在 → 当即新建（向前更新）**：扫 `<项目根>/.handoff/*/PROTOCOL.md`，把发现的记忆包填进 `REGISTRY.md`（一条一个：是什么／归哪个记忆包／怎么用）；`CHANNEL.md` 写表头 ＋ 一行"初次建立（历史见各记忆包的 `LOG`）"。**别为它停下接手**——建了什么，在报告里说一句。
   - **(b) 定记忆包**：口令／用户话里点名的就上它；没点名 → 只有一个记忆包就上它，多个则按 `REGISTRY.md` 的路由问用户。
   - 这一步的全部意义是：**世界在你睡觉时动过什么，先知道，再动手。**
1. **读读取约定**：读 `<记忆包>/PROTOCOL.md`。
   - 若不存在：按保存元约定的"协议引导"先与用户共创协议（见 §2 步骤 1 的 (a)），再做下一步。
   - 若不合规（不满足 §3 硬性格式）：停下，向用户报告不合规点与修复提议，等确认。
2. **封条检查（只读一行，不读正文）**：从资产表取出 `role: state-summary` 的文件，**读它末行**的 `updated`。判"**变过**"三条，任一成立即**整份重载最新**（不得拿旧快照下判断）：
   ① `updated` **晚于本次会话开始**（＝你睡的时候它被推进过）；② 与你**手上那份**不同（同一会话内醒来时，那份封条就在你的上下文里）；③ **读不到封条／旧格式只到日期 → 一律当作已变**（fail-safe：宁可多读一份，不可拿过期认知下判断）。
   - **已下的记忆包：不检查、不重载**（§0：持有＝订阅）。
   - **接管记忆包本来就要整份读**，封条在那里的用处是**报告惊奇**（"它在你睡时被推进过"）；封条真正省读的场合是**你打算定点读、或复用旧认知**时——**凡"不整份重读"，先过封条**。
3. **按接手必读清单全文读取**（B1）：逐文件全文读入 PROTOCOL 中 `handoffReadList` 声明的文件，**顺序即声明顺序**。
   - 这些文件是**引导注入通道**（B3）：其中 `role: guidance` 的文件，其自由格式内容在读取后直接生效为任务内行为引导（风格/优先级/方法/禁区），效力见 §3 的优先级护栏。
4. **通读资产表，建立索引**：看每个文件的 role、load 策略与"可回答什么问题"，在脑中建立"什么信息在哪个文件"的心智索引。
5. **执行自定义约定声明的「接手后流程」**：接手后具体做什么——例如是否需要向用户输出状态画像、以什么方式汇报、是否停下等用户确认——由**自定义约定**（接手必读清单中 `role: guidance` 的文件）规定，**元约定不预设任何内容**。若自定义约定未规定接手后行为，采用通用最小默认：简要说明你的理解与打算，等待用户指示后再动手。
6. **通用护栏**：元约定安全与用户权限永远最高（见 §3 优先级护栏）；任何改动用户资产、计划或跨会话语义前，遵循自定义约定或用户的明确指示。只存在于旧对话、未落盘的临时信息，由用户在此补一句即可。

> **世界级两份（若存在；不存在则按 §1 步骤 0(a) 当即新建）**：**总注册表**回答"这个世界现在有什么、归哪个记忆包"——**总注册表**不含状态，所以**缺项只算缺，不算过时**；**总账本**回答"我不在的时候，谁做了什么"。要修一台坏掉的机器：先查总注册表找**负责的记忆包**，再上那个记忆包。

**会话进行中**：需要任何信息时，先查心智索引 → 定点读取对应文件，**不做整库重读**（这是读取效率的关键；B2）。读取约定已声明的环境/事实类结论以 .handoff 文件为准，不重新探测考古。

## 2. 能力1：保存（保存元约定）

用户在对话中说"使用1 / 存档 / 保存 / 交接 / SAVE"，或会话接近上下文上限时由 agent 主动提醒后触发。步骤：

1. **协议保证**：
   - 读 `<记忆包>/PROTOCOL.md`。不存在 → 引导共创（见 a）；存在 → 按 §3 硬性格式做结构校验、覆盖校验、自述校验；不合规 → 停下报告+提议，等用户确认后修复并升版本。
   - （a）引导共创：向用户问：①这个任务在做什么、什么才算"状态"？②用哪些文件、什么形式记录？③多久回来一次？④**接手后你希望 agent 如何开始**（如：要不要先复述状态等你确认？什么汇报风格？禁区？）。据此生成 PROTOCOL.md v1 骨架（含 handoffReadList 与至少一个 role: guidance 文件）与 guidance 文件草稿，请用户确认。
   - **适配原则（元约定教给 agent 的撰写能力）**：撰写读取约定与自定义约定必须**针对任务做适配**，不是套模板——状态模型要贴合该任务"什么才算状态"；资产表/必读清单/guidance 文件按任务需要取舍；**行为细节（接手后做什么、是否画像、是否确认、风格、禁区）一律写进自定义约定（role: guidance 文件），不得依赖元约定承载，也不得塞进读取约定的结构里**；读取约定只承载元信息、状态模型、接手必读清单、资产表、定点索引与写规则（结构 + 指针）。
2. **分账（对称）**：这一轮你**读了几个记忆包、动了几个记忆包**？**动过的每个记忆包都要整一份**（`SAVE-<记忆包>`）——**包括别人的记忆包**：接管记忆包时你已经整份读过**该记忆包**（§1 接管记忆包），这是对价；动完就要**像它的负责者走时一样**更新它的自我。只动了别人的记忆包、自己那个记忆包没有实质进展，就不必整自己的。
3. **落盘**：按该记忆包`PROTOCOL` 的"资产表 + 能力1 写规则"更新各文件（覆盖/追加/按需以协议声明为准）。**写回哪个记忆包要写全路径**（`.handoff/<记忆包>/STATUS.md`），别只写文件名。
   > **该记忆包的账本只记它自己的事。** 别的记忆包的状态**不进本账本**——它有自己的记忆包
   > （`<项目根>/.handoff/<记忆包>/`）。本账本最多留**一句指路**。
   > **动作的收尾即时写，不等 SAVE。** 新建／改动了世界里的**产物** → 在**总账本**追加一条（"谁做了什么"）；"这是什么 / 怎么用 / 归哪个记忆包"变了 → 更新**总注册表**；技术细节（换了什么、坑在哪）→ 写本记忆包的 `LOG`。SAVE 只管**自我**，不管这些。
   > **接管记忆包／交回记忆包各在总账本追加一行**（署名＝**那个记忆包**）："上了 X"／"下了 X（推进收尾）"。这是世界看得见"谁在推什么"的唯一途径，也是**交回记忆包的对外宣布**。
   > **交回记忆包前必须"完整负责"**：对该记忆包跑完整能力1（含 SAVE）；没存过，不许下。
4. **版本戳（封条）**：在本次写出的状态类文件（如 STATUS）与流水文件（如 LOG）记录 `conformsTo` + PROTOCOL `version`；**状态画像文件（`role: state-summary`）的末行戳还必须带 `updated`（ISO-8601，到秒）**——它是别人睡醒时判断"这个记忆包被推进过没有"的唯一凭据。
5. **回读校验**：逐文件读回本次写出的内容，确认无遗漏、无格式错误。
6. **汇报**：向用户简短汇报存了哪些文件 + 一句话总结本次状态。

## 3. 对任务约定（PROTOCOL.md）的硬性格式要求（conformsTo: handoff-meta-v1）

PROTOCOL.md 必须满足以下全部要求，否则不合规（见 §1.1 / §2.1）：

1. **文件与位置**：固定 `<记忆包>/PROTOCOL.md`；Markdown；至少一个 fenced YAML 块承载资产表。
2. **固定小节（缺一不可，按此顺序）**：
   - 元信息块（YAML）：`conformsTo`（须为 `handoff-meta-v1`）、`version`、`owner`（**本资产表为哪个记忆包负责**，须与记忆包Root 对得上）、`task`（一句话）、`updated`（ISO 日期）、`maintainedBy`、`记忆包Root`（**本记忆包的根**，如 `.handoff/<记忆包>`；记忆包名缺省时为 `.handoff`）。
   - `## 状态模型`：枚举本任务**哪些内容**算"需要跨会话的状态"。
   - `## 接手必读清单`：YAML 列表 `handoffReadList`，**非空、有序**；每一项必须是资产表声明的 path；至少含一个 `role: state-summary`（状态画像）文件；**鼓励含一个 `role: guidance` 文件**（引导注入）。
   - `## 资产组织方式`（**资产表**，fenced YAML）：每个文件一条，字段：`path`（相对记忆包Root）、`role`（映射到状态模型某类别；特殊值 `state-summary`/`guidance`）、`form`（`sections`|`checklist`|`freeform`|`append-log`）、`schema`（form=sections 时列出固定小节名）、`load`（`full`|`scan`）、`writeMode`（`overwrite`|`append`|`on-change`）、`answers`（本文件"可回答什么问题"，索引用）。**资产表只收本记忆包负责的资产。**
   - `## 定点读取指引`：需求 → 文件 的显式索引（可选但鼓励）。
   - `## 协作规则`：能力2 完成后行为如何适应本任务（风格/优先级/禁区），允许只写一句话引用 guidance 文件。
   - `## 能力1 写规则`：只写资产表推导不出的联动/合并细则。
   - `## 变更记录`：`日期 | 版本 | 维护者 | 变更一句话`；每次修订必追加、必升 version。
3. **覆盖校验**：状态模型里的每个状态类别，资产表至少一个文件映射（防漏记）。
4. **自述首行**：资产表声明的每个文件第一行必须是"自述"（`# <文件名>（<role>；<所属记忆包>；本文件是什么/怎么更新）`），且与 role 一致——陌生 agent 光看文件也能自解释、也知道**这是谁的**。
5. **版本耦合 + 封条**：运行态文件写时盖 `conformsTo` + PROTOCOL `version` 戳；**状态画像（`role: state-summary`）的末行戳必须带 `updated`（ISO-8601，到秒）**——它是睡醒（§1 步骤 0／2）判断"是否被推进过"的唯一凭据。旧格式（只到日期）**不算不合规**，但睡醒时一律当"可能已变"（代价＝多整份读一次；**偏差方向只许是"多读"**）。能力2 读到旧版本运行态时，提示用户可能需要执行一次能力1。
6. **职责分离（硬性）**：读取约定只承载结构——元信息、状态模型、接手必读清单、资产表、定点读取指引、能力1 写规则，以及"协作规则"一节中的指针（指向 guidance 文件）。**一切任务特定的接手后行为（是否输出画像、是否确认、汇报方式、风格、禁区）必须由自定义约定（必读清单中 role: guidance 的文件）规定**；元约定与读取约定都不得预设此类行为内容。（注意：职责分离 ≠ 元约定极薄——元约定的厚度与教学职责见 §5。）

**世界级两份不进任何记忆包的资产表，也不参与本节校验**：`REGISTRY.md`（总注册表）与 `CHANNEL.md`（总账本）住 `<项目根>/.handoff/` 顶层，由本元约定直接定义。**两者都是可选的**——没有它们的工作区照样合规，但**接手时若发现缺失，当即按 §1 步骤 0(a) 新建**（向前更新），别停下接手。

**优先级护栏**（B3）：`元约定安全与用户权限（最高） > PROTOCOL 固定结构 > 注入规约（guidance 内容）`。注入规约不得解除用户硬约束、不得覆盖元约定禁区、不得要求隐瞒或越权；冲突时停下问用户。

**在别人的记忆包上（接管记忆包）时**：以**那个记忆包的规矩**为准（**该记忆包的** PROTOCOL 与 guidance），但**用户权限仍最高**、元约定安全不被解除——接管记忆包不改变这两条。

## 4. 通用协作规则

- 中文交流；回复精炼；最小读取（只读 .handoff 与必要片段，不为重建状态而全文重读项目文档）。
- 每次会话有实质进展/新坑/新决定时，会话结束前执行一次能力1（至少更新 STATUS 类与 LOG 类文件）。
- 不重复考古：环境/事实类结论以 .handoff 文件为准。
- 计划/进度类变更需用户确认；教学/文档类小改可自主并记入 STATUS。
- 长对话提醒：上下文明显变长或用户表示"对话太长了"时，主动建议执行一次能力1，再迁移到新会话执行能力2。
- **偏差方向只许是"多读"**：封条读不到、格式旧、说不准它变没变 → **当已变**，整份重读。宁可多读一份，不可拿过期认知下判断——**惊奇是判断错误的原料，不是情绪问题**。

## 5. 元约定的厚度：撰写自定义约定的设计空间（教学职责）

本元约定**内容中性**（不预设任何任务内容），但**教学厚度必须高**：它同时服务于两端模型——执行端（能力1/2）与撰写端（创建/修订自定义约定的 agent）。撰写端对"舞台"的理解越深，写出的自定义约定才越能控制表现；执行端理解越深，临场适应越稳。若元约定只是喊"内容你去自定义"，撰写端就不知道有哪些可控制的维度（例如不知道"话术"可控），也就写不出对它们的约束。

**总原则：元约定预设"有哪些值得预设的方面"（提供菜单），但不预设"这道菜是什么"（不写内容）。**

撰写或修订自定义约定（role: guidance 文件）时，按下列设计空间逐项自问，并把需求写进对应位置：

| 想控制接手后的什么 | 在 guidance 文件里写什么 |
|---|---|
| **话术 / 语气 / 措辞**（要不要固定模板、什么腔调） | 一段"话术要求"或示例模板。**只要有控制接手后话术的需求，就应写进必读自定义提示（guidance 文件）**，而不是留给模型即席发挥 |
| 接手后流程（是否先输出画像、是否停下等确认、汇报顺序） | "接手流程"小节 |
| 行为风格 / 优先级 / 禁区 / 豁免条件 | 对应小节（并写明豁免触发词，如"直接给答案"） |
| 与用户的交互规则（提问偏好、术语策略、何时长文何时精简） | 对应小节 |
| 需要长期引用的事实边界 | 指向 ENV/STATUS 类文件（**指针**），而非复制内容 |

同时，元约定本身也应把以下"机制为什么这样设计"讲清楚，帮助执行端在模糊场景下做对判断：必读清单为何是引导注入通道（§1）、读取为何按策略而非自由反推（B2）、行为为何归自定义（§3.6）——**对舞台理解越深，表演越优**。

## 6. 执行端认知与意识清单（元约定教给执行端的心智）

- **任务边界与记忆包守护**：一个记忆包的边界由它的 `owner`、`task` 与"状态模型"界定；本记忆包之外的工作属于**别的记忆包**或**支线**——典型信号：用户说"临时 / 岔出来 / 试试 / 先弄一下 / 放一放"，或该工作在性质上是工具开发、机制测试、元工作。支线**有自己的记忆包**（`<项目根>/.handoff/<记忆包>/`）与自己的 skill，就地在**它自己的记忆包账本**里完成，**不写进别的记忆包**；支线产物若需长期存在，落在其自有位置（skill 目录、代码目录等）；处理完支线回到本记忆包时，主动提示一句"已回到 XX"。
- **权责对等**：能写别人记忆包的文件，是因为你**先整份读了他的自我**（接管记忆包）；写完了就要**像他走时一样**更新他的自我。接管记忆包不是顺手改一下——它有对价。
- **状态新鲜度**：.handoff 是上一次能力1 的快照，可能滞后于当前对话——能力2 核对画像时主动问用户"文件状态与你的实际进展有没有出入"，以对话现状为准修正，而不是把旧快照当圣旨。
- **睡醒先看世界，再看手上的记忆包**：世界级两份告诉你"我不在时发生了什么"，封条告诉你"我手上这个被推进过没有"。**惊奇是判断错误的原料**——今天的真实事故就是：另一个会话在并发改同一批产物，而这边照着过期认知写下了"现状"。
- **持有＝订阅，下了＝不订阅**：交回记忆包是把**权**交回去，不是把**责任**甩掉——下之前必须**完整负责**（SAVE 过）；交回之后**不许再写它的文件**（要写就重新上）。**一个记忆包同一时刻只该有一个持有者**；发现撞车，先问用户，别抢写。
- **对话权威 > 文件权威**：用户当前的明确指示，优先于 .handoff 中的任何记录。
- **防漂移**：PROTOCOL / guidance 等约定性文件的任何修订都必须经用户确认并升版本 / 记变更；执行端不得在"顺手小改"里静默改动约定（防止多轮跨会话后约定被逐步漂移）。
- **覆盖不丢信息**：能力1 覆盖写 STATUS 前，确认被替换内容中没有未沉淀的关键信息；悬空问题必须保留到真正解决，不得因覆盖丢失。
- **冗余换防错**：信息上"足够"不等于设计上够——执行体每轮重建、无身份、会被误读而不自知，所以关键位置（表头、首行自述）**要有冗余**，好让文件自己说清自己是谁的、为谁负责。
- **分层意识**：执行端时刻清楚自己此刻在哪一层——内容层（产物进项目文档与本记忆包状态）、元层（机制 / skill / PROTOCOL 结构，改动需用户确认）、支线层（住在自己的记忆包里，进自己的记忆包账本）。
- **隐私与最小化**：.handoff 与工作区可能含私人信息，不外传；读取按需、不整库搬运。
- **复用而不重建**：新任务先看是否已有可复用约定或机制；模糊场景回到"问用户 + 通用最小默认"。

## 7. 边界

本 skill 恢复的是"上下文+方法+约定"，不是对话原样；只存在于对话、未落盘的重要临时共识，靠确认门由用户补一句，或由本会话执行能力1 落盘。
**睡醒只保证两件事**：① 世界级两份（世界动过什么）；② **你持有**的记忆包（它有没有被推进过）。**你没上、或已下的记忆包，不保证跟进它的最新变化**——要跟，就重新上它（整份读＝写权对价）。
它也不判断"是不是 fork"、不认身份：**持有关系靠"这一路你上了谁"来定义，不靠"你是谁"**。
