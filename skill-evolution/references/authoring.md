# 作者培训包（岗位：作者）

> 这是 `skill-evolution/references/` 的第三层：**不在目录里、不随正文加载**——读到 `SKILL.md` §5 的指针，才知道它存在。
> 读者：要**起草新技能**、或**重写某个技能的形态**的人（接手会话 B / 评估 fork F）。
> 读完用 `skillctl train authoring` 登记；没有这条记录，`add` 会拒。

## 0. 先判：这东西该不该做成 skill

四条**同时满足**才晋升（引擎 §4）：① 跨任务可复用；② 有明确触发条件；③ 有可执行步骤；④ 踩过坑、有代价。
外加**互补铁律**：只编码「模型不会、但这里必须会」的本地知识。模型本来就会的（怎么写代码、怎么用 git）不进 skill——
那只会稀释目录、拉低触发精度。

**找不到真实摩擦就别写**：为"看起来有产出"写 skill，是这台机器上最贵的表演（下个月还在，会被下一个你读到）。

## 1. 起草前，先回答三个问题（必须写进正文首段）

1. **我什么时候该被领？** —— 写 `description`：覆盖什么领域、什么症状下该查我。
   **只写场景，不写优先级**（"先走我 / 默认走我"越界；判据是"谁授予"，见引擎 §1.1）。
2. **领到我之后，按什么顺序读？** —— 渐进披露：正文是**索引**，`references/` 按处境分岔。
   哪几份必须先读、哪几份按需，写清楚；**没有条件的边等于没有边**。
3. **我的权责边界？** —— 能改什么、不能改什么、要谁批、改动要留什么沿革。
   一个不写边界的 skill，等于让下一个执行体自己发明边界。

## 2. 先判层级

- **Level 1（能力/流程类）**：摩擦是「某类任务怎么做」→ 走 §3。
- **Level 2（机制/元协议类，即自我存续器官）**：摩擦是「agent 自身怎么跨会话存在」→ 走 §4。
  **质量标杆 = `session-handoff`**（元层面适配各类工作接续，泛化 + 特化结合）；本引擎自身也是同一标准的产物。

## 3. 起草 Level 1（能力/流程）

1. **判定**：一次性 vs 一类（过 §0 四条件 + 互补铁律）。
2. **抽象**：找「这类事怎么应对」的稳定步骤，不写「这次怎么解」的病历。
3. **触发器**：一句话「当……时，用本 skill 做……」写进 `description`。
   **这句话要和用户会说的原话、以及你会感觉到的症状对齐**——否则触发不了，等于不存在。
4. **步骤/清单/排错**：procedure + checklist + 排错速查；**覆盖不丢信息**（被替换的正文里没有未沉淀的关键内容）。
5. **可脚本化则脚本化**（引擎 §2 的"机器"类：不必进上下文，因为它替你把事做对）：
   重复劳动能固化就写进 `scripts/`；**代价一起算**——脚本要维护、要能被下一个人跑起来，只值一次的事别固化。
6. **自解释**：正文第一段让陌生模型立刻知道「这是什么、何时用、怎么用」。
7. **边界**：明确「不教什么、不碰什么」——这不是免责声明，是给读者的判据。

## 4. 起草 Level 2（机制类培训包）的 12 条不变式

在 §3 之上追加（同一套抽象方法推进到更难的 meta 类问题，不是独立配方）。逐项自问，缺一即返工：

1. **元协议声明**：本 skill 不承载具体内容，只承载机制 + 教学。
2. **固定锚点**：存储根、协议文件位置、格式版本戳写死。
3. **硬编码算法**：核心流程固定顺序、不得自由反推。
4. **结构 vs 行为分离**：结构文件只放指针 + schema，行为归专用文件（如 guidance）。
5. **教学厚度**：教执行端「心智」，教撰写端「哪些维度可控」的菜单（只喊"内容自定义" = 无效教学）。
6. **优先级护栏**：用户权限 > 固定结构 > 注入内容；冲突停问。
7. **版本耦合 + 防漂移**：运行态盖戳；约定改动须用户确认 + 升版本。
8. **自解释**：每个资产首行自述 + 正文首段冷启动可重建。
9. **覆盖不丢信息 / 对话权威 > 文件权威 / 复用而不重建**。
10. **边界**：明确「恢复什么、不恢复什么」。
11. **入口自查**：它的 `description` 是否让人（和下一个你）在该想起来的时候想得起来？
    这是 meta 类 skill 最容易死的地方——**机制再漂亮，叫不醒也等于没有。**
12. **权责落点（v15 新增）**：把"系统要求你"翻译成"你有资格了，所以该做什么、什么时候算做完、做完交回"。
    参照 `session-handoff` 的样板：**持有＝订阅 / 下了不写 / 整份读是写权的对价 / 下之前必须完整负责**。
    没有这一条，机制只有"该有什么"，没有"为什么下一个执行体愿意守"。

## 5. 建图：正文是索引，references 是分支

- **边带条件**：每一条指向 `references/x.md` 的句子，都要写"当……时读它"。
- **节点自足**：一份 reference 离开来路也能单独读懂，不许"如前所述"。
- **树是默认，DAG 允许**：一个 reference 服务多个处境是合法的（省重复、少漂移）；**不要为"单亲"复制文件**。
- **跨包单向**：技能包可以指向包外的东西（比如 store、引擎的培训包），但**必须显式**——包一搬家就断。
- **不许成环**：环让"整份读"变成"读不完"。
- **深度 ≤ 3 跳**：再深就说明你在用文件树代替决策树。

`check` 能机械抓到四种结构错：目标不存在、孤儿引用（没人指到）、成环、深度 > 3（警告）。
**"条件写清没有""节点自足没有"它判不了**——那是你起草时要负责的部分。
