# skill-evolution 设计（v16，已实现）

> 状态：**已实现**。当前仓库交付的就是这一版（引擎 v16 / 数据格式 v4）。
> 读者：要改引擎的人。先读 `../SKILL.md` 的承重规则与 `../scripts/skillctl.js`，再读这里。
> 上一版设计（v2 备忘，未实现）在 git 历史里；它描述的"18 个命令收成五个动作"已经落地。

## 1. 三条根认识

1. **机器在进步，不是因为模型在进步。** 执行体每轮重建；能积累的只有文件（skill、references、沿革、账本）。
2. **摩擦是唯一的真实信号，且只能来自机器外面。** 绕远路、重复踩坑、被用户纠正——这些症状本身就是调用引擎的理由。
3. **判断留在文本，确定压成程序。** 脚本只做确定性操作与报告，永不自行决定晋升/淘汰。

## 2. 两条道

| | 运行时 | 治理 |
|---|---|---|
| 是什么 | `skills/<name>/`：`SKILL.md` ＋ `references/` ＋ `scripts/` | `.evolution/history/<name>/`：观察与提案 |
| 服务谁 | 用它／干这类活的人 | 改它／有权改的人 |
| 怎么读 | 公告 → 加载正文 → 按需读 references | `self <name>` 整份读 |

两者之间只有一条**单向指针**（治理指向运行时）。**技能自己不认识治理包**——加载一个技能，不该顺带拉进它的全部历史。

## 3. 分发图（第一性）

一条知识只有在**被读到**时才存在。设计问的不是"它多重要"，而是"**它挂在哪张图的哪个节点上、谁在第几步读到它**"。

- **节点**：承载文本的位置（目录行、SKILL.md、references、AGENTS.md、沿革条目、账本、用户消息）。
- **边**：一段文本让读者去打开另一个节点。**只要有文本，就能加边。**
- **根**：不需要动作就在上下文里的节点（目录行每轮、`AGENTS.md` 每会话一次）。
- **深度**：到根的最短跳数——每多一跳，多一次"读不读"的赌注和一次上下文成本。

### 3.1 四条边规则

1. **边带条件**：写清"当……时，读它"。没有条件的边等于没有边。
2. **节点与路径无关**：离开来路也能单独读懂；读者顺着条件进来，**条件就是来路**。
3. **跨包单向**：治理 → 运行时可以；运行时 → 治理不许。包是分发单位，包外的一搬家就断。
4. **不许成环**：环让"整份读"变成"读不完"。

### 3.2 树是默认，DAG 合法

包内默认成树（一个根、一支一个处境）——好算成本、好推理。但**允许 DAG**：一个节点服务多个处境是合法的，
只要它自足、每条边各带条件。**"两个父亲 ⇒ 不知道从哪条路进来"是错的**：读者就是顺着某个条件走进来的。
共享节点省重复、少漂移；两处各抄一份才是双倍维护。

所以 `check` 不卡"单亲"，只卡结构上真会坏的四种：**目标存在、无孤儿、无环、深度 > 3（警告）**。
"条件写清没有""节点自足没有"判不了——归作者培训（`references/authoring.md`），不归 `check`。

### 3.3 图之外：须知

图只说明"到得了"，不说明"你为什么会在这里"。只有边，模型会机械地在节点间旅行——被上一段文字带到下一段，不知道自己在受训。
**须知**（运行时根上的 `AGENTS.md`）给的是定位：这是培训、不是岔路；这些材料有归属、有来历。

图做不到而须知能做到的三件事：① 把"读一份 reference"识别成**上课**，而不是检索答案（所以读全，不摘取）；
② 发现"该领的包不在"时主动去找，而不是就地发挥；③ **拒绝一条不该走的边**。

## 4. 沿革条目：唯一形态

字段：`id / at / kind / scope / cause[] / type / state / why / evidence[] / by / sessions[] / pin / legacy?`

- **kind**：`观察`（撞过的壁 ＋ 那一眼）｜`提案`（要改什么、为什么）。
- **state**：观察 `open → reviewed`；提案 `open → merged | rejected | superseded`；通用 `archived`。
- **正文不可变**：文件名 = `<日期>-<id>-<正文哈希8位>.md`，`check` 重算。要改就新开一条、旧的置 `superseded`。
- **永不删**：只追加、只改状态。历史没有回滚面——git 只保护"提交过的中间态"，而被否决那一刻最没人提交。

同一形态消灭了三族旧事故：覆盖即销毁（正文不可变）／accepted 的 why 全空（why 一等）／changelog 被单行 YAML 截断（变更即条目）。

## 5. 五个动作

| 动作 | 命令 | 要资格吗 |
|---|---|---|
| **记** | `note --what --lesson --scope --cause --type` | 不要 |
| **读** | `self <name>` ／ `train authoring` | —（它**产生**资格） |
| **提** | `propose <name> --why` ／ `supersede` | 不要（没资格只能提） |
| **批** | `merge <name> --why` ／ `reject --why` | **要**（读记录＋fresh＋批准者≠作者＋check） |
| **扫** | `view` ／ `check` | 不要 |

## 6. 三门与上岗纪律

| 门 | 卡什么 | 谁卡 |
|---|---|---|
| **格式门** | 条目 schema、正文哈希、evidence、引用图、包哈希 | 程序（`check`，**卡在 merge 路径上**） |
| **资格门** | 改技能前读过该技能的沿革；造技能前读过作者培训 | 可对账的事实（`reads.jsonl`） |
| **权威门** | 单一写入口、正文不可变、提案钉整包哈希 | 程序 ＋ 人的确认门 |

**上岗纪律**（写在运行时根的 `AGENTS.md`）：会改变持久资产的动作——改技能、改 store/约定、对外发布、动别人的包——**先领对应的包**；
没领过，只能读、只能提。文本管"知不知道"，机器管"做不做得到"。

## 7. 分类三维

- **cause（5 值）**：`task`（任务固有）／`user`（用户意志）／`agent-class`（凡 LLM 执行体）／`model`（本模型族易犯）／`harness`（平台）。
- **type（8 值封闭）**：未经对账的断言／覆盖即销毁／本机工具约定／写完没回读／顺序做反／定位误判／验证工具本身没验／交付形态未适配读者。
- **scope（自由）**：registry 里的技能名，或 `无归属`。

闭合理由（实测）：v15 之前 20 条账出现过 **19 个不同 type**、scope/by/cause 全空 ⇒ "分账建包"这一棒从没发生过。
自由文本让"复发"无法聚合；要加枚举值 → 引擎修订（慢档），不许临场造词。

## 8. 命令面

`init`／`list`／`show`／`add`／`set`／`promote`／`sync`／`render`／`roundtrip`／`stale`／`review`
＋ 五个动作（`note`／`self`＋`train`／`propose`＋`supersede`／`merge`＋`reject`／`view`＋`check`）。
旧名保留为别名（`friction add / accept / lint / report`）。**没有 delete；没有直接写正文的命令。**

## 9. 与 v13 的差别

| 项 | v13 | v16 |
|---|---|---|
| 账本 | `friction.jsonl`（一行一条）／`proposals/*.md`／changelog／archive 四套 | 沿革包一种：`history/<name>/entries/*.md`，一条一文件、正文不可变 |
| 归属 | 摩擦无 scope/by/cause | 三字段必填；type 封闭枚举 |
| 资格 | 无 | `self` 留读记录；`merge` 前校验；`train authoring` 是造技能的资格 |
| 提案 | 钉 SKILL.md 单文件哈希 | 钉**整包**哈希（SKILL.md＋references＋scripts） |
| 门 | `lint` 只报告 | `check` 卡在 merge 路径上 |
| 命令 | 18 个 | 五动作族 ＋ 登记巡检；旧名做别名 |
| 作者教学 | 在正文里（每次加载都背） | `references/authoring.md`（随包分发，按需领取） |

## 11. 我们错在哪（留档，别重犯）

1. **把"不在运行时加载"当成"不在技能包里"** —— 于是把作者培训挪到包外。错在忘了**包是分发单位**；渐进披露是包内的层次。
2. **从"树是成熟形态"推出"必须单亲"** —— 观察直接跳规范。"两个父亲 ⇒ 不知道从哪进来"是假的：条件就是来路。
3. **把沿革画进技能目录**（更早的一版）—— 运行时与治理绑在一起。现在用"归属看属于哪个自我"讲清：
   作者培训属于引擎的自我；某个技能的沿革属于那个技能的治理包。
